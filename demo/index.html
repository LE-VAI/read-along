read-along

An embeddable web component for bimodal reading: synchronized word highlighting while the text is spoken aloud. Drop it around any content, press Listen, and the words light up as they're read — for dyslexic readers, language learners, tired eyes, and anyone whose hands are busy.

The case for reading along

Reading while listening — bimodal reading — is one of the best-evidenced assistive techniques there is. A 2017 meta-analysis across dozens of studies found that text-to-speech support measurably improves comprehension for readers with disabilities, and the effect is strongest when the highlighting follows the voice word by word.

Yet almost nothing open exists for the web. Screen readers read everything, indiscriminately. Commercial tools lock the technique behind subscriptions. The humble read-along — the format that taught a generation to read with turn-the-page chimes on cassette tapes — never got its open-source web component. Until now.

What's inside

The component tokenizes your content without touching its markup, maps every word to a live Range, and paints the active word with the CSS Custom Highlight API — no span-wrapping, no DOM churn, your links and styles untouched. Under the hood it defeats Chrome's infamous fifteen-second speech cutoff by speaking in sentence-sized chunks with a keep-alive heartbeat, and it interpolates word timing when boundary events don't fire.

The speech engine is pluggable: Web Speech by default, or bring your own — a local neural voice in WASM, or pre-synthesized audio with a timing manifest, like the cards on this page's older sibling.

Guaranteed visible: the fallback path

Some embedded browsers expose the highlight registry but never paint it — an invisible highlight, the worst failure mode there is. When you need certainty, the force-fallback attribute wraps the active word in a real mark element instead: a touch of DOM churn, but it renders in every engine that runs this component at all.
